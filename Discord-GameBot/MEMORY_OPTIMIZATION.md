# 通常時・バックアップ・読み上げのメモリ対策

- Discordのメッセージキャッシュを100件に制限します。新しいメッセージのコマンド処理、XP加算、読み上げは引き続き処理します。キャッシュ範囲外の過去の投稿は、今後編集・削除イベントの機能を追加するときにrawイベントや明示的な取得を使ってください。
- 毎分のバックアップは2つのSQLiteを同時にロックして整合したスナップショットを作成し、ロックを解除した後にファイルを順次ハッシュ化・ZIP圧縮します。アップロードもファイルをストリームとして送り、再試行ではファイルを先頭から開き直します。従来のZIP形式、チェックサム、復元処理、アップロード上限は維持しています。
- VOICEVOXエンジンとTTS Questの読み上げ音声は最大64KiBのチャンクでファイルへ保存します。音声全体をメモリに保持するクロージャは使いません。取得サイズ上限、TTS Questの配信先・話者・WAV確認は維持します。中止・失敗時の途中ファイルも削除します。
- 読み上げ停止時は実行中タスク、待機文、設定キャッシュ、通知の待機時刻を解放します。個人設定やサーバー設定はSQLiteから再読み込みでき、削除しません。
- VC退出時は先読み・準備処理を終了させ、ダッシュボードの最終更新後に空の音楽セッションを解放します。再参加や新しい曲の追加があった場合は、利用中のセッションを削除しません。
- 確認したゲームの終了処理はすでに登録解除を行っていたため、動作中のゲームの削除や一律のメモリ掃除は追加していません。

Pythonの確保済みメモリがOSへすぐ返るとは限らず、MWS上でのRSS削減量は実測が必要です。YouTube取得ワーカーの負荷は別に残ります。起動時のバックアップ復元とGoogle TTS互換APIには、既存のサイズ上限付きバイト読み込みを残しています。
