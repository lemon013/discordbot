# プレイヤーデータのDiscord保存

クラウド起動 (`cloud_main.py`) では、チャンネル `1571130824697323582` をプレイヤーデータの保存先として使います。チャンネルを変更する場合のみ `PLAYER_BACKUP_CHANNEL_ID` を設定します。既存の `LEVEL_DB_PATH=/levels.sqlite3` はそのまま使えます。追加のAPIキー・依存ライブラリは不要です。

専用添付 `gamebot-player-data.zip` にXP・レベル・設定・ジュエル・履歴・ショップ購入/装備・ブラックジャック・レベル報酬記録などのSQLite DB全体を保存します。`shop-entitlements.json` とMinecraft成績の転送ファイルは変更しません。トークンや `.env` は添付しません。

## 動作

- 起動時、Bot自身が送信した専用バックアップをチャンネル履歴から探します。履歴は必要に応じて全ページを検索します。
- DBサービスを作る前にバックアップを取得し、チェックサム・SQLite整合性・必須テーブルを確認して両DBを読み込みます。取得/検証/権限確認に失敗した場合は起動しません。
- 初回だけバックアップが存在しないことを確認したうえで現在のDBから開始します。以前消えたデータを推測して復旧する機能はありません。
- ローカルに前回保存済みの記録とDBが残っている通常の再起動では、それ以降の変更を含むローカルDBを優先します。
- Discord接続後すぐに保存し、以後60秒ごとに同じメッセージの添付を更新します。両DBは同じ時点の状態で取得します。保存失敗はログへ表示し、次回再試行します。
- 更新・突然停止でローカルが消えた場合、最後にDiscordへの保存が成功した状態から開始します。通常は最大約1分、通信障害中はそれ以上の未保存分が失われる場合があります。

## 必要なDiscord権限

クラウドBotに「チャンネルを見る」「メッセージを送信」「ファイルを添付」「メッセージ履歴を読む」を付与してください。バックアップにはユーザーIDや経済データが含まれるため、このチャンネルは非公開にしてください。Botはこれらの権限を起動前に確認します。

バックアップメッセージは削除しないでください。同じBot・同じチャンネルを使い続け、同じ保存先を使うBotを同時に複数起動しないでください。添付は9MB以内（展開後64MB以内）です。超えた場合はログにエラーを表示するため、永続DB等への移行が必要です。Discord側のメッセージが消去された場合まで保証する仕組みではありません。

起動ログの `Loaded complete player databases from Discord backup` が読み込み成功、`Player data saved to Discord channel ...` が保存成功です。設定・移行を含むローカル保存については `LEVELING_README.md` も参照してください。
